# ai/ — инструкции для ИИ-агента (ML/LLM)

Сначала прочитай корневой `AGENTS.md` и `shared/api.md`. Здесь — правила именно для `ai/`.

## Роль модуля

Вся ИИ-логика проекта: парсинг документов, вызовы LLM, промпты, проверка источников.
Наружу модуль отдаёт **Python-пакет** с одной точкой входа
`run_analysis(before_files, after_files, on_progress) -> AnalysisResult` (схема — `shared/api.md`).
Бэкенд импортирует его (`pip install -e ../ai`). Для автономной проверки есть CLI `python -m ai.cli`.
Пайплайн (10 шагов) и golden-тест на ред. 8/9 описаны в `ARCHITECTURE.md`, раздел 4.

**Главное правило задачи:** каждый вывод должен иметь `Evidence` (документ + пункт + точная цитата), и цитата
проверяется кодом (`ai/evidence.py`). Вывод без проверенного источника не попадает в заключение.

## Стек

- Python 3.11+, зависимости в `ai/requirements.txt` (или `pyproject.toml`), виртуальное окружение `ai/.venv`.
- LLM-провайдеры: **OpenAI** (основной) и **NVIDIA API** (`https://integrate.api.nvidia.com/v1`, OpenAI-совместимый — тот же SDK `openai`, другой `base_url` и ключ).
- Парсинг: `python-docx` (DOCX), `pymupdf` (PDF), `openpyxl` (XLSX).

## Структура

```
ai/
  ai/pipeline.py    ← run_analysis(...) — оркестратор шагов
  ai/parsing.py     ← чтение файлов + нарезка на пункты (clause_id), без LLM
  ai/units.py       ← извлечение и сопоставление подразделений
  ai/functions.py   ← функции: потери, дубли, конфликт интересов
  ai/evidence.py    ← проверка цитат кодом
  ai/report.py      ← итоговое заключение
  ai/llm.py         ← единый клиент: call_llm(...), эмбеддинги, провайдеры, ретраи, кэш
  ai/schemas.py     ← Pydantic-схемы (совпадают с shared/api.md)
  ai/prompts/       ← промпты отдельными файлами (.md), не строками в коде
  ai/cli.py         ← запуск из терминала → JSON
  experiments/      ← скрипты для проб (не импортируются пакетом)
  evals/            ← golden-набор: ожидаемые находки для тестовых документов
  pyproject.toml, .env.example, README.md
```

## Правила

1. **Один клиент LLM.** Все вызовы моделей — только через `core/llm.py`. Провайдер выбирается через `LLM_PROVIDER` (`openai` | `nvidia`), модель — через env (`OPENAI_MODEL`, `NVIDIA_MODEL`). Смена провайдера = смена одной переменной.
2. **Ключи только из env:** `OPENAI_API_KEY`, `NVIDIA_API_KEY`. Никогда не печатай, не логируй и не коммить их.
3. **Структурированный вывод.** Когда ответ идёт в код — требуй JSON (structured output / JSON mode) и валидируй Pydantic-схемой. Невалидный ответ → одна повторная попытка → fallback.
4. **Надёжность:** таймаут на каждый запрос, 1–2 ретрая при сетевых ошибках/429, при отказе основного провайдера — fallback на второй. Если всё упало — **демо-заглушка** с правдоподобным ответом (флаг `AI_DEMO_FALLBACK=true`), а не 500.
5. **Экономия кредитов ($50 OpenAI, $50 NVIDIA):** для экспериментов — дешёвые модели, ограничивай `max_tokens`, никаких вызовов LLM в бесконечных циклах, кэшируй повторяющиеся запросы в экспериментах.
6. **Промпты версионируй:** правишь промпт — прогоняй `evals/` до и после, пиши результат в README (раздел «Качество»).
7. **Не выдумывай названия моделей и параметры SDK.** Проверь установленную версию `openai` и документацию.
8. **Заглушка первой:** до готовности модели в `mocks/result.json` лежит `AnalysisResult` на данных ред. 8/9, чтобы бэкенд и фронт интегрировались сразу.
9. **Парсинг и нарезка — без LLM.** `clause_id` определяется кодом по нумерации, модель только ссылается на существующие `clause_id`.
10. **Не выдумывай.** В промптах явно требуй: использовать только текст документов, при отсутствии подтверждения — не делать вывод.

## Запуск (обнови в README, если меняется)

```bash
cd ai
python -m venv .venv && .venv\Scripts\activate   # Windows
pip install -e .
cp .env.example .env                              # и вписать ключи
python -m ai.cli --before ../samples/before/*.docx --after ../samples/after/*.docx > result.json
```
