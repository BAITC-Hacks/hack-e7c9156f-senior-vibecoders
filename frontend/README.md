# Frontend: анализ организационной структуры

## Что это

React-интерфейс для сравнения документов до и после реорганизации в стиле Kazakhtelecom Business. В локальном режиме читает выбранные файлы в браузере и сравнивает весь извлечённый текст; при подключении backend показывает также аналитические выводы и источники.

## Быстрый старт

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

Откройте http://localhost:5173. Без настройки переменных запускается локальный режим: загрузка двух файлов показывает их текст и технические различия, а кнопка «Запустить демо-комплект» показывает фиксированный короткий пример. Для подключения к backend укажите `VITE_USE_MOCKS=false` в `.env` и запустите backend на порту 8000.

## Переменные окружения

| Имя | Зачем | Пример |
|---|---|---|
| `VITE_USE_MOCKS` | `true` включает чтение файлов и демо в браузере, `false` вызывает backend. Пустое значение включает локальный режим. | `true` |
| `VITE_API_URL` | Базовый URL backend. Пустое значение означает `http://localhost:8000`. | `http://localhost:8000` |

На фронтенде нет секретных ключей: все `VITE_` значения доступны браузеру.

## API / интерфейс

Все запросы проходят через `src/api/client.ts`; типы ответов находятся в `src/api/types.ts` и повторяют `../shared/api.md`. Сейчас интерфейс принимает один файл «до» и один «после». В локальном режиме сетевых запросов нет.

| Запрос | Назначение |
|---|---|
| `POST /api/analyses` | Отправка `FormData`: повторяющиеся поля `before` и `after` с файлами. Ответ: `{ "id": "a1b2" }`. |
| `POST /api/analyses/demo` | Запуск серверного демо-комплекта. Ответ: `{ "id": "a1b2" }`. |
| `GET /api/analyses/a1b2` | Статус, например `{ "id": "a1b2", "status": "running", "step": "units", "progress": 0.4 }`. |
| `GET /api/analyses/a1b2/result` | Итоговый `AnalysisResult` после статуса `done`. |
| `GET /api/analyses/a1b2/documents/r9/clauses/3.4` | Текст пункта: `{ "clause_id": "3.4", "text": "..." }`. |
| `GET /api/analyses/a1b2/report.docx` | Необязательный экспорт отчёта; кнопка в режиме backend скачивает файл или показывает ошибку, если эндпоинт недоступен. |

Экраны: **Документы** → **Анализ** → **Результат**. Вкладка **Сравнение документов** показывает весь извлечённый текст старой и новой редакции в двух прокручиваемых колонках, в исходном порядке. Служебные номера фрагментов не показываются. Добавленный текст выделен синим, удалённый — красным. Есть фильтр изменений и переход между ними. Остальные вкладки: заключение, подразделения, функции, перемещение функций и риски. Кнопки «Источник» открывают пункт документа и подсвечивают цитату.

Вкладка **Функции** показывает категорию из `categories`, статус, уверенность и источники каждого `function_mappings[]`. **Перемещение функций** строит Sankey из `flows[]`: ширина линии равна числу функций, нажатие открывает их названия и источники; цель `lost` обозначает потерянные функции. **Риски** отдельно показывает подтверждённые `findings[]` и опровергнутые `rejected_findings[]`, решение критика, контраргументы и `rule_id` для конфликтов интересов. **Подразделения** показывают `rationale`, состав подразделений, должности и источники.

Вкладка сравнения читает `documents[].clauses` и `alignments[]` из `AnalysisResult`. Каждый пункт из `documents[].clauses` показывается даже без сопоставления; `alignments[]` добавляет подсветку и навигацию. В локальном режиме `src/api/localPreview.ts` извлекает текст из DOCX, текстовых PDF и XLSX. DOCX отображается по абзацам, PDF — по строкам страниц, XLSX — по строкам листов. В режиме backend он должен вернуть весь извлечённый текст в `clauses`.

## Статус

- Работает загрузка одного файла на сторону, чтение текста выбранных файлов в локальном режиме, демо-кнопка, опрос прогресса, сравнение пунктов, вывод результата и панель источника.
- Для загруженных файлов локальный режим показывает только текст и технический diff; выводы ИИ и риски не вычисляются. Фиксированный пример из `src/api/mocks.ts` открывается только по кнопке «Запустить демо-комплект». Его текст условный, а цитаты помечены как непроверенные.
- В режиме backend интерфейс использует реальный API. Экспорт DOCX доступен при наличии необязательного серверного эндпоинта.
- Сканированные PDF без текстового слоя требуют OCR на backend; локальный режим сообщает, если текст не извлечён.
- Сравнение показывает извлечённый текст без исходного оформления, страниц и таблиц Word/Excel.
- Сравнение нескольких файлов пока не поддерживается: для этого в `ClauseAlignment` потребуются идентификаторы документов.
- Известное ограничение: форматирование `conclusion_md` поддерживает обычный текст и жирное выделение, без полного Markdown.

## Как проверить

```bash
cd frontend
npm run build
npm run dev
```

Откройте страницу, выберите реальные PDF или DOCX «до» и «после», нажмите «Сравнить тексты файлов» и проверьте весь текст без служебных номеров строк, фильтр и стрелки изменений. Для XLSX проверьте извлечённые строки. Затем вернитесь к загрузке и нажмите «Запустить демо-комплект»: появится фиксированный пример с аналитическими вкладками. Проверьте вкладки «Функции», «Перемещение функций» (нажмите на линию) и «Риски» (включая отклонённый вывод). Для реального API задайте `VITE_USE_MOCKS=false` и повторите сценарий с запущенным backend.
