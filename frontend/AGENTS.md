# frontend/ — инструкции для ИИ-агента (React + TypeScript)

Сначала прочитай корневой `AGENTS.md` и `shared/api.md`. Здесь — правила именно для `frontend/`.

## Роль модуля

То, что увидит жюри. Интерфейс общается **только с бэкендом** (`http://localhost:8000`), никогда напрямую с `ai/`.
Экраны (загрузка «до/после» → прогресс → результат с вкладками и панелью «Источник») описаны в `ARCHITECTURE.md`, раздел 6.
Главная ценность UI — **прослеживаемость**: у каждого вывода кнопка «Источник» с документом, пунктом и подсвеченной цитатой.

## Стек

- React + TypeScript, сборщик Vite, пакетный менеджер — npm (не смешивать с yarn/pnpm).
- Стили: Tailwind CSS (+ по желанию shadcn/ui для готовых компонентов).
- Запросы: `fetch` через единый API-слой.

## Структура

```
frontend/
  src/api/client.ts    ← единственное место с fetch; базовый URL из VITE_API_URL
  src/api/types.ts     ← TS-типы запросов/ответов (совпадают с shared/api.md)
  src/api/mocks.ts     ← моки по контракту
  src/components/      ← переиспользуемые компоненты
  src/pages/           ← экраны
  .env.example
  README.md
```

## Правила

1. **Все запросы — через `src/api/client.ts`.** Базовый URL — `import.meta.env.VITE_API_URL` (по умолчанию `http://localhost:8000`).
2. **Типы = контракт.** `src/api/types.ts` повторяет `shared/api.md`. Не используй `any` для данных API.
3. **Моки с первой минуты.** `VITE_USE_MOCKS=true` — клиент возвращает данные из `mocks.ts` без бэкенда. Так фронт не ждёт бэк.
4. **Каждый запрос имеет три состояния в UI: загрузка, ошибка, данные.** ИИ-ответы могут идти несколько секунд — покажи понятный индикатор, а не замерший экран.
5. **Ошибки показывай человеку** понятным текстом, не пустым экраном и не только в консоли.
6. **В `.env` фронта нет секретов.** Всё с префиксом `VITE_` попадает в браузер. Никаких API-ключей LLM на фронте — только через бэкенд.
7. **Демо-сценарий в приоритете:** главный экран и основной флоу должны выглядеть аккуратно и работать без перезагрузок. Адаптив — хотя бы чтобы не ломалось на ноутбуке и проекторе.
8. **Проверяй в браузере** после изменений: `npm run dev`, открой страницу, пройди сценарий, проверь консоль на ошибки. `npm run build` должен проходить без ошибок TypeScript.

## Запуск (обнови в README, если меняется)

```bash
cd frontend
npm install
cp .env.example .env
npm run dev      # http://localhost:5173
```
